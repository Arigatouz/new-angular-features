Resource snapshot

Every resource() / httpResource() exposes snapshot: Signal<ResourceSnapshot<T>> — one atomic read of the whole state as a discriminated union on status. Drive the controls and watch a single @switch narrow the type per branch.

Controls
@let snap = userRes.snapshot();
A

Four separate signals

isLoading()
{{ userRes.isLoading() }}
status()
{{ userRes.status() }}
hasValue()
{{ userRes.hasValue() }}
value()
{{ userRes.hasValue() ? userRes.value().name : '—' }}
error()
{{ userRes.error()?.message ?? '—' }}

Five independent reads you correlate by hand. status() is just a string — it does not tell TypeScript whether value() or error() is meaningful, so you guard manually.

B

One snapshot()

status: {{ snap.status }}
@switch (snap.status) { @case ('idle') {

idle — no request in flight. No value yet.

} @case ('loading') {

loading — fetching the first value…

} @case ('reloading') {

reloading — previous value stays available: {{ snap.value?.name }}

} @case ('resolved') {

resolved — {{ snap.value?.name }} <{{ snap.value?.email }}>

} @case ('local') {

local (set via .set()) — {{ snap.value?.name }}

} @case ('error') {

error — {{ snap.error.message }}

} } 
{{ snap | json }}

Composition · resourceFromSnapshots

Click Load user 1 then Load user 2. A switch to a different request goes through loading, so the raw resource blanks its value. The composed resource maps that snapshot to reloading and keeps the previous value on screen — no flash of empty.

Raw userRes

status {{ userRes.status() }}

value {{ userRes.hasValue() ? userRes.value().name : '—' }}

Composed stickyRes

status {{ stickyRes.status() }}

value {{ stickyRes.hasValue() ? stickyRes.value().name : '—' }}

Chaining · ctx.chain(userRes)

posts: {{ postsSnap.status }}

The posts resource chains off the user resource. Toggle Force error or Set idle above and watch this snapshot follow the upstream — ctx.chain throws the user's status when it is not resolved, so you never fetch posts for a user that failed to load.

@switch (postsSnap.status) { @case ('idle') {

idle — upstream user is idle, so no posts request is made.

} @case ('loading') {

loading — waiting on the user, then the posts…

} @case ('reloading') {

reloading — {{ postsSnap.value.length }} posts (stale)

} @case ('resolved') {

resolved — {{ postsSnap.value.length }} posts for this user

} @case ('local') {

local — {{ postsSnap.value.length }} posts

} @case ('error') {

error — propagated from the user: {{ postsSnap.error.message }}

} }
